A clearer template designer

Three ways to make building a table (sections, sub-sections, rows and cells) easier to find your way around. All three keep the dense, grey look and use PrimeNG controls only. Nothing here is built yet: pick one and I'll implement it.

What gets in the way today

  • Two trees side by side. The table list and the structure outline look the same and sit next to each other, so it isn't obvious which one you're in. Together they also squeeze the table preview to about a third of the screen.
  • The outline stops at sections. Rows and cells aren't in it. To reach a row you go to its section's settings and pick it from a list, or right-click a cell. Nothing in the outline lights up when you click a cell.
  • Every level looks alike. Header, section and sub-section are plain text with no icon, and column blocks sit under a separate grey heading, so the depth isn't readable at a glance.
  • Adding and moving are scattered. "+" on hover in the outline, "Add row" in the section panel, "Insert cell" only in the right-click menu, and moving only through up/down buttons in each panel.
  • The settings panel is one long scroll. The breadcrumb wraps onto three lines, back/forward arrows duplicate it, and a cell's type, placement, kind settings and style are stacked with no way to fold them.

The same in every option

  • One icon per level, used in the tree, the breadcrumb, menus and panel titles. Colour is only on these small icons.
  • A one-line selection bar above the preview: the breadcrumb of what's selected, each crumb clickable to jump up a level, plus the actions for that level. It replaces the wrapping breadcrumb and the back/forward arrows in the settings panel.
  • The table list folds away once a table is open: it becomes a narrow rail with a "Tables" button that opens it as a PrimeNG drawer, and the table name in the toolbar is a picker to switch tables.
  • The settings panel uses folding groups (PrimeNG Panel, toggleable): General, Placement, Type settings, Style. Each group header shows a count of overridden values. Delete sits with the actions in the selection bar rather than at the bottom of the panel.
  • Clicking anything selects it everywhere: the canvas, the tree (or gutter) and the panel stay in step, and Esc selects the parent.

Option A: full structure tree Recommended

The outline becomes the complete structure: table, header, sections, sub-sections, rows and cells, each with its icon and a short summary. Hovering a node shows "+" (add the natural child) and "⋯" (the same menu as right-click). Nodes drag to reorder or move into another section (PrimeNG Tree drag and drop), with a drop line showing where they'll land. A filter box at the top finds a cell by caption.

The tree shows every level, so the selected cell is always visible in context. Rows are labelled with their first captions so "Row 2" means something. The selection bar carries the actions for the selected level; for a section it would show Add row, Add sub-section and Delete.

  • Add: "+" on a node adds its natural child (section → row, row → cell). The "⋯" menu and right-click offer everything else, such as Insert row above.
  • Move: drag in the tree, or Alt+↑/↓ on the selected node. The up/down buttons in the panels go away.
  • Cost: mostly front-end. The tree, selection bar and panel groups are new components; moving a row or sub-section into a different parent needs one new API endpoint.

Option B: canvas first, structure in a gutter

No separate outline column. The preview takes the full width, and a narrow labelled gutter on its left shows which section, sub-section and row each line belongs to, with a coloured edge for depth. Clicking a gutter label selects that level. Hovering between rows shows a thin "+ Add row" line. A "Structure" button opens the full tree in a popover for jumping around big tables.

Rows and sub-sections are picked in the preview or the gutter.

The structure lives next to the lines it describes, so the preview is the one place you work. Shown with a sub-section selected and the Structure popover open.

  • Add: the "+ Add row" line under the last row of each section, the selection bar's buttons, and right-click.
  • Move: drag a gutter label up or down, or the arrow buttons in the selection bar. Moving to another section is done through the "⋯" menu ("Move to…").
  • Trade-off: the most room for the table, but deep tables get a busy gutter, and a horizontal table's column blocks need their own strip across the top. More work in the canvas, which is the most complex part of the designer.

Option C: a Structure grid and a Layout preview

Two tabs over the main area. Structure is a PrimeNG TreeTable of the whole table: one line per section, row and cell with editable columns for type, caption, required, column and span, so most edits happen inline without the side panel. Layout is today's preview, for checking how it looks and fine-tuning spans and style. The side panel stays for detailed settings of the selected line.

A spreadsheet-like view of the structure: fast for engineers who want to set up many cells, and the hierarchy is the indentation.

  • Add and move: one toolbar above the grid that acts on the selected line, keyboard friendly (arrow keys to move through lines, Enter to edit).
  • Trade-off: the quickest for bulk set-up and the clearest hierarchy, but you no longer see the layout while you change the structure, so spans and column blocks are harder to picture. Two places to edit the same thing (grid and panel) needs care.

Recommendation

Option A. It fixes the main complaints directly: the outline becomes a real map of the table with every level and a clear icon, it follows whatever you click, adding and moving happen in one consistent place, and the folded-away table list gives the preview most of the screen back. It keeps the preview you already use and is the least work. Option C's inline editing could be added later as a "Grid" tab if bulk set-up turns out to be a pain.
