One status for every row, on every table

Three ways to show a row's version, who has it, and where it is on the way to being published. The same component would be used on vertical and horizontal tables, for limits, parts and anything else built from a template.

What a row can say

Every row carries two facts. Its version is the publish that last changed it (v7), or New if it has never been published. Its state is exactly one of the five below. Colour says whose it is, the icon says what state, and the words say both, so nothing depends on colour or a tooltip.

Sent back by an approver is not a sixth state: the row returns to Draft with the approver's reason shown in the action bar. Tables, sections and column blocks use the same five states in their headers.

The same in all three options

  • Toolbar summary. Counts for the whole sheet, each a filter: drafts (yours and others'), awaiting approval. This answers "what would this publish take".
  • Action bar sentence. Selecting a row spells its status out in full, with the actions that apply (request takeover, discard, approve).
  • Changed cells. The grey corner on a cell changed since the compared version stays as it is.
  • Colour rule. Blue is yours, amber is someone else's, purple is waiting for approval, green is publishing.

Option A: a status column Recommended

Every table gets one narrow pinned column at the left. It reads the same on any table because it never depends on what the first data cell happens to be.

For. Version, state and name are readable at a glance for every row. Identical on vertical and horizontal tables. Data cells carry no row marks at all.
Against. Costs about 9rem of width on every table. It can collapse to icon and initials on narrow screens.

Option B: a caption inside the first cell

Closest to today. The left-edge bar takes the state's colour, and the small version text under the first cell grows into a full status line.

For. No extra column. Smallest change from what exists.
Against. Every row gets about a quarter taller. The line is small (10px) and is clipped when the first column is narrow, which on a horizontal table it often is.

Option C: an edge stripe and a pending list

The grid shows only a coloured stripe and an icon. Names and versions live in a list of everything pending on the sheet, above the tables, and in the action bar for the selected row.

For. The quietest grid. The list is a natural place to review and approve from.
Against. In the grid you cannot see who has a row or what version it is on without selecting it or looking it up in the list. Rows at rest show no version.

Recommendation

Option A, plus the pending list from option C as the body of the publish dialog, so "what is being published" is a list of rows and not just a count. The status column is the only choice that works unchanged on every table shape, and it keeps the status out of the data.

What approval would need

Nothing here exists yet, so "For approval" would stay unused until it is built. The smallest version:

  • Data. A third revision status, Submitted, beside Draft and Published, and a submission record (sheet, who submitted and when, note, decision, who decided and when, reason). One database migration.
  • Permission. A new sheets.approve. People with sheets.publish submit; people with sheets.approve approve or send back. Approving creates the numbered version exactly as publishing does today.
  • Rules to settle. Whether approval is required on every sheet or switched on per sheet type, and whether someone may approve their own changes (suggested: no).
  • Screens. Publish becomes "Submit for approval" where approval is on; approvers get a review list with Approve and Send back.
